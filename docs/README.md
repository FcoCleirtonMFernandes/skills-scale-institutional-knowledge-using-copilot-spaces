# OctoAcme Project Management Docs

This folder contains the core project management guidance used by OctoAcme. Together, these documents define how the team initiates work, plans delivery, runs execution, manages risk and communication, releases software, and reflects on improvements.

## Project management overview

OctoAcme moves work through a repeatable lifecycle: initiation, planning, execution, release, and retrospective. Initiation validates the business problem, confirms stakeholders, defines measurable outcomes, and produces a lightweight one-pager and go/no-go decision. Planning turns approved work into a prioritized backlog, compiles milestones and dependencies, estimates effort, and defines a shared Definition of Done. During execution, the team uses a project board, daily standups, backlog reviews, and structured pull request workflows to build and validate small, testable increments. Releases require acceptance criteria, CI and security checks, smoke tests, release notes, and rollback guidance before changes go live. Retrospectives capture lessons learned and convert them into a small set of owned, time-bound improvement actions.

## Cross-cutting practices

Across the lifecycle, OctoAcme emphasizes clear ownership, continuous communication, and quality by default. Project roles are explicitly defined so the team understands who leads outcomes, who coordinates delivery, and who executes the work. Communication practices include daily standups, weekly delivery updates, demos, stakeholder check-ins, and escalation paths for blockers or incidents. Quality is reinforced through standard PR requirements, automated linting and test checks, security scanning, manual QA when needed, and release smoke tests before production deployment.

## How to use this set of docs

Use the overview as the starting point for understanding the operating model. Move to the specific document that matches the phase or activity you are working on, and keep the relevant artifacts — one-pager, risk register, backlog, release notes, and retrospectives — updated as the project progresses.
